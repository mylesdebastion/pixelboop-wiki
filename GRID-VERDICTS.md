## Reachability of the NEEDS-STATE grids (added after checking the source)

Not all outstanding grids can be settled in a simulator. Verified against v1.1.3:

**HARDWARE-GATED, a simulator can never reach these:**

- `ConfigModeDemo`, `ChannelCycleDemo` (Connectivity) - entry to MIDI config mode
  is gated on `MIDIService.isMIDIReady`, which is
  `connectionState == .connected && midiDestination != 0`
  (MIDIService.swift:148). That needs a real BLE MIDI peripheral. The iOS
  Simulator has no CoreMIDI/Bluetooth hardware, so this state is unreachable.
  Settle these on a device with the Erae Touch or a Roland/Korg unit attached.
- `SyncOverview`, `SyncButtonStates`, `FollowerSession`, `HostSession`,
  `OrchestraMode`, `DeviceIndicatorsDemo` - multi-device sync runs over
  MultipeerConnectivity (Services/MultipeerTransport.swift). A second peer is
  required. Settle these with two real devices.
- `WLEDButtonDemo` and the WLED "output on" band - the drifting colour band only
  animates when WLED output is enabled against a device. The config DIALOG is
  reachable (tap opens it), the connected state is not.

**NOT CAPTURABLE BY TAP-THEN-SCREENSHOT (tooling limit, not hardware):**

- `BankDisplayDemo` - the preset-cycling display only exists WHILE the finger is
  held on column 0. Tap and screenshot are separate calls, so the state has
  reverted by capture time; a 700ms hold was tried and returned the plain idle
  gradient. To settle this, run `xcrun simctl io <udid> recordVideo` in the
  background, perform the hold, stop the recording and pull a frame from the
  middle. Same applies to any other hold-to-reveal display.

**SIMULATOR-REACHABLE, still to do:**

- `MuteDemo` - partially done; chords/bass/rhythm muted values still unmeasured.
- `SectionOverview`, `SectionPlayDemo`, `SectionPlayButtonDemo` - sections are
  in-app, reachable by tapping the section lane.

So the remaining work is NOT uniformly "more simulator driving". Roughly half of
the outstanding state grids need physical hardware and should be batched into a
single device session rather than attempted here.
